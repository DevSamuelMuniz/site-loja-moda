DOCUMENTAÇÃO DO PROJETO — PLATAFORMA DE E-COMMERCE PARA LOJAS DE MODA

1. VISÃO GERAL

Este projeto é uma plataforma moderna de e-commerce voltada inicialmente para lojas de moda e vestuário.

O objetivo não é criar apenas um site institucional ou uma vitrine estática. O projeto deve evoluir para uma plataforma completa de vendas online, permitindo que uma loja cadastre produtos, controle estoque, receba pedidos, gerencie clientes, configure sua identidade visual e acompanhe suas vendas por meio de um painel administrativo.

A aplicação atual funciona como um modelo/base visual de uma loja de moda. A partir dela, o sistema deverá ser transformado em uma solução funcional, escalável, configurável e preparada para ser reutilizada por diferentes lojas.

O projeto deve preservar a qualidade visual e a experiência de usuário do site atual, mas adicionar toda a infraestrutura necessária para operação real de um e-commerce.

3. PRINCÍPIO FUNDAMENTAL

O projeto deve ser tratado como um PRODUTO/SISTEMA, e não como uma página web isolada.

Não criar funcionalidades simuladas apenas visualmente quando elas deveriam estar conectadas ao backend.

Sempre que uma funcionalidade depender de dados persistentes, ela deve ser estruturada para funcionar com banco de dados, autenticação, regras de negócio e APIs.

Exemplo:

ERRADO:
- Criar um produto apenas em um array fixo no frontend.

CORRETO:
- Produto armazenado no banco.
- Produto carregado pela API.
- Produto associado a uma loja.
- Produto possui estoque e variações.
- Alterações feitas pelo administrador refletem automaticamente na loja pública.

40. PRINCÍPIO DE DESENVOLVIMENTO PARA IA

Ao modificar ou desenvolver este projeto, a IA deve:

- Ler este documento antes de implementar funcionalidades.
- Entender que o projeto é uma plataforma de e-commerce.
- Preservar funcionalidades existentes.
- Evitar reescrever partes estáveis sem necessidade.
- Não criar dados fictícios como substituto de backend real.
- Não implementar apenas interfaces falsas.
- Priorizar arquitetura sustentável.
- Reutilizar componentes.
- Manter responsividade.
- Manter acessibilidade.
- Validar dados no frontend e backend.
- Considerar segurança.
- Considerar multi-tenant desde a modelagem quando aplicável.
- Criar código organizado e tipado.
- Evitar dependências desnecessárias.
- Documentar decisões importantes.
- Não quebrar funcionalidades existentes.
- Testar fluxos críticos após alterações.

42. VISÃO DE LONGO PRAZO

Este projeto deve se tornar uma base reutilizável para criação de lojas virtuais profissionais.

A ideia é possuir uma única plataforma capaz de gerar diferentes lojas através de configurações.

Exemplo:

PLATAFORMA
|
+-- Loja de roupas femininas
+-- Loja de roupas masculinas
+-- Loja infantil
+-- Loja de calçados
+-- Loja de acessórios
+-- Loja de cosméticos

Cada loja possui identidade própria, mas utiliza a mesma infraestrutura.

O foco deve ser criar um sistema robusto, configurável, visualmente profissional e fácil de administrar.


43. REGRA FINAL

Antes de implementar qualquer funcionalidade, verificar:

1. Essa funcionalidade pertence à loja pública ou ao painel?
2. Precisa de persistência no banco?
3. Precisa de autenticação?
4. Precisa de controle de permissão?
5. Precisa respeitar o tenant?
6. Afeta estoque?
7. Afeta pedidos?
8. Afeta pagamentos?
9. Afeta analytics?
10. Precisa ser configurável pelo lojista?

O projeto deve sempre ser desenvolvido pensando em produto real, não apenas em demonstração visual.

A interface atual é o ponto de partida. O objetivo final é uma plataforma completa de e-commerce para lojas de moda.
